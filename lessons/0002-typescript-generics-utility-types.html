Lesson 2: Generics & Utility Types

The gatekeeper topic in TypeScript rounds. Mid-to-senior interviews live here — this is where candidates get filtered.

Mission: Pass a backend engineer interview · See also: Glossary

Why This Matters

Interviewers report that ~35% of TypeScript questions focus on the type system — generics, unions, and utility types. A candidate who can write a generic helper and compose utility types demonstrates real TS depth, not just surface familiarity. This lesson gets you there.

1. Generics: The Core Idea

Generics are type parameters. They let a function, class, or type work with any input type while preserving the relationship between input and output.

function identity<T>(value: T): T {
  return value;
}

const num = identity(42);       // type: number
const str = identity("hello");  // type: string

Without generics, you'd use any and lose all type safety. With generics, TypeScript infers the type from usage.

Constraints

Use extends to limit what types are allowed while staying generic:

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { name: "Ada", age: 30 };
getProperty(user, "name");  // OK, returns string
getProperty(user, "email"); // Error: 'email' not in keyof User
Interview inflection: "I use extends keyof T to constrain the key parameter so callers get autocomplete and I get type-safe access. Without it, key would be string and the return type would be T[string] instead of the specific property type."

Multiple Type Parameters

function pair<A, B>(a: A, b: B): [A, B] {
  return [a, b];
}

const p = pair(42, "hello"); // type: [number, string]

2. Built-In Utility Types

These are the most commonly asked utility types. You need to know what each does and when to reach for it.

UtilityWhat it doesExample
Partial<T>All properties optionalPATCH request body
Required<T>All properties requiredStrict config validation
Readonly<T>All properties readonly (shallow)Immutable snapshots
Pick<T, K>Select subset of keysDTO projection
Omit<T, K>Remove subset of keysExclude sensitive fields
Record<K, V>Object type with keys K, values VDictionary / lookup
ReturnType<T>Extract return type of functionDerive from typeof fn
Parameters<T>Extract parameter types as tupleWrapper / middleware
Awaited<T>Unwrap Promise typeAsync function return
Exclude<T, U>Remove members of U from union TFilter union members

Real-world patterns

// PATCH endpoint — only send updated fields
interface User { id: number; name: string; email: string; }
type UpdateUserPayload = Partial<Omit<User, 'id'>>;

// Derive type from an existing function (no duplication)
async function fetchUser(id: number): Promise<User> { ... }
type FetchUserResult = Awaited<ReturnType<typeof fetchUser>>; // User

// Typed dictionary
type Role = 'admin' | 'user' | 'guest';
type Permissions = Record<Role, string[]>;
Shallow trap: Partial<T> and Readonly<T> are shallow. They only affect the top level. For nested objects, you need a recursive deep version — interviewers love this as a follow-up.

3. How Utility Types Work (Mapped Types)

Utility types aren't magic — they're mapped types. Understand the pattern and you can write any utility.

// Pick from scratch — iterate over keys K, keep their types
type MyPick<T, K extends keyof T> = {
  [P in K]: T[P];
};

// Partial from scratch — make every key optional
type MyPartial<T> = {
  [P in keyof T]?: T[P];
};

// Record from scratch — map keys K to values V
type MyRecord<K extends keyof any, V> = {
  [P in K]: V;
};

The syntax [P in keyof T] means "for each property P in T." The ? modifier makes it optional. readonly works the same way.

Interview script: "Mapped types iterate over keys with [K in keyof T]. That's how Partial, Pick, and Record work internally. If an interviewer asks me to implement Pick, I write { [P in K]: T[P] } with a constraint K extends keyof T."

4. Discriminated Unions

A discriminated union is a union type where each member has a literal property (the "discriminant") that TypeScript uses to narrow in switch / if blocks.

type ApiResult<T> =
  | { status: 'success'; data: T }
  | { status: 'error'; message: string }
  | { status: 'loading' };

function handleResult(result: ApiResult<User>) {
  switch (result.status) {
    case 'success':
      // result.data is typed as User — narrowed by status
      console.log(result.data.name);
      break;
    case 'error':
      // result.message is typed as string
      console.error(result.message);
      break;
    case 'loading':
      // No data or message — only this variant
      break;
  }
}
Exhaustiveness check: Add a default branch with never to catch when you add a new variant but forget to handle it: 
default: const _exhaustive: never = result; // Error if a case is missing

5. Conditional Types

Types that depend on a condition — like a ternary at the type level.

// If T is a string, resolve to 'yes', otherwise 'no'
type IsString<T> = T extends string ? true : false;
type A = IsString<'hello'>;  // true
type B = IsString<42>;       // false

// Extract element type from an array
type Flatten<T> = T extends Array<infer U> ? U : T;
type C = Flatten<string[]>;  // string
type D = Flatten<number>;    // number

The infer keyword captures a type variable inside the conditional — used to extract Promise values, function returns, array elements.

6. Interactive Puzzles

Puzzle 1: What is the type of result?

interface User { id: number; name: string; email: string; }
type Result = Pick<User, 'id' | 'name'>;

Answer: { id: number; name: string; }

Puzzle 2: What's wrong with this code?

function first<T>(arr: T[]): T {
  return arr[0];
}

const val = first([1, 2, 3]); // type: number — OK

first([1, 'a', true]); // what type is inferred?

Answer: number | string | boolean — TypeScript infers the union of all element types. This is actually correct behavior: generics preserve the relationship, and the element types are mixed.

Puzzle 3: Implement Omit from scratch using Pick and Exclude.

Answer:

type MyOmit<T, K extends keyof T> = Pick<T, Exclude<keyof T, K>>;

Internally, Exclude<keyof T, K> removes the excluded keys from the union of all keys. Then Pick selects only the remaining keys.

Puzzle 4: What does this mapped type do?

type Nullable<T> = {
  [K in keyof T]: T[K] | null;
};

type User = { id: number; name: string };
type Result = Nullable<User>;

Answer: { id: number | null; name: string | null; } — every property becomes nullable. This is a custom mapped type (not built-in) but follows the same pattern as Partial and Readonly.

Puzzle 5: Narrowing with discriminated union

type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number };

function area(s: Shape): number {
  // What goes here?
}

Answer:

function area(s: Shape): number {
  switch (s.kind) {
    case 'circle':
      return Math.PI * s.radius ** 2;
    case 'square':
      return s.side ** 2;
    default:
      const _exhaustive: never = s;
      return _exhaustive;
  }
}

TypeScript narrows s inside each case — s.radius exists only inside case 'circle', s.side only inside case 'square'. The default: never catches missing cases at compile time.

7. Interview Answer Script

When the interviewer asks "Tell me about generics and utility types":

"Generics are type parameters — they let me write a function or type that works with any input while preserving the type relationship. I use extends to constrain when I need access to specific properties.

"For utility types, I reach for Partial on PATCH bodies, Pick and Omit for DTO projections, Record for typed dictionaries, and ReturnType combined with Awaited to derive types from existing functions instead of duplicating them.

"I know these work via mapped types — [K in keyof T] — and I can implement Pick or Partial from scratch if needed. For complex state, I use discriminated unions with an exhaustiveness check so the compiler catches unhandled cases."

8. Common Follow-Up Questions

Q: "What's the difference between type and interface?"

A: interface supports declaration merging (reopening) and is conventional for object shapes. type is more flexible — it handles unions, tuples, mapped types, and primitives. Use interface for public APIs you may extend; type for everything else.

Q: "How would you type an API response that could succeed or fail?"

A: A discriminated union: { ok: true; data: T } | { ok: false; error: string }. Narrow on ok. Add a third variant like { ok: 'loading' } for async states. This gives compile-time safety — no invalid property access.

Q: "What does satisfies do (TS 4.9+)?"

A: satisfies checks that a value conforms to a type without widening it. Example: const config = { port: 3000 } satisfies Record<string, unknown> — config.port stays number, not unknown. Use it to validate an object's shape while keeping the narrowest types.
