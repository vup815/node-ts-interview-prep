Node.js 面試

Lesson 3: Streams & Buffers

Node.js 第二常考的深入題。Streams 是 Node 處理大量資料時不爆記憶體的方式。

先修：Lesson 1（Event Loop）

為什麼重要

面試官考 streams 是想知道你知不知道 Node 怎麼處理真實世界的大規模資料。誰都會用 readFileSync 讀檔案 — 知道什麼時候、為什麼用 streams 才是後端工程師和腳本工人的差別。

1. Streams 解決的問題

// 不好的做法 — 一次載入整個檔案到記憶體
const fs = require('fs');
const data = fs.readFileSync('huge-file.log', 'utf8');
// 記憶體用量：等於整個檔案大小（可能 500MB）

// 好的做法 — 一個 chunk 一個 chunk 處理
const readStream = fs.createReadStream('huge-file.log', 'utf8');
readStream.on('data', (chunk) => {
  console.log(`收到 ${chunk.length} bytes`);
});
// 記憶體用量：一次只佔 ~64KB（預設 highWaterMark）

沒用 streams：等整個檔案/回應都載入到 RAM，才開始處理。
用 streams：資料一到就處理，一次只處理一小塊。

2. 四種 Stream 型別

型別方向範例
Readable來源 → 你fs.createReadStream、HTTP request body
Writable你 → 目的地fs.createWriteStream、HTTP response
Duplex雙向TCP socket、WebSocket
Transform串流中修改資料zlib.createGzip、加密
// Readable：讀取資料
const readable = fs.createReadStream('input.txt');

// Writable：寫入資料
const writable = fs.createWriteStream('output.txt');

// Transform：資料通過時修改（像翻譯員）
const { Transform } = require('stream');
const upperCase = new Transform({
  transform(chunk, encoding, callback) {
    callback(null, chunk.toString().toUpperCase());
  }
});

// 用 pipe 串起來：讀 → 轉換 → 寫入
readable.pipe(upperCase).pipe(writable);
// "hello" → "HELLO" → 寫進 output.txt

3. Pipe — 核心概念

.pipe() 是 glue。它把 Readable stream 接到 Writable stream，並自動處理 backpressure。

// 用 HTTP 串流檔案 — 面試經典範例
const http = require('http');
const fs = require('fs');

http.createServer((req, res) => {
  // 直接串流檔案到 response
  // 不用等整個檔案讀完
  const stream = fs.createReadStream('big-video.mp4');
  stream.pipe(res);
}).listen(3000);

stream.pipe(res) 做了三件事：

  1. 從檔案讀取 chunk
  2. 寫入 HTTP response
  3. 如果 response 比檔案讀取慢，自動暫停讀取（backpressure）

4. Backpressure — 最難的部分

Backpressure 是當寫入端跟不上讀取端時發生的狀況。沒處理好，資料會一直累積在記憶體，最後 crash。

// pipe() 內部做的事：
const readable = fs.createReadStream('source.txt');
const writable = fs.createWriteStream('dest.txt');

readable.on('data', (chunk) => {
  const canWriteMore = writable.write(chunk);
  if (!canWriteMore) {
    // 目的地不堪負荷 — 暫停來源
    readable.pause();
    writable.once('drain', () => {
      // 目的地準備好了 — 恢復讀取
      readable.resume();
    });
  }
});
面試陷阱：如果你自己監聽 'data' 事件然後呼叫 .write() 但沒處理 backpressure，資料會無上限地在記憶體中累積。這就是為什麼 .pipe() 是安全的預設做法 — 它會自動處理 backpressure。

5. Buffer — 原始二進位資料

Buffer 是一塊固定大小的原始記憶體，配置在 V8 heap 之外。每個 stream chunk 預設就是 Buffer（除非你指定 encoding）。

// 從字串建立 Buffer
const buf = Buffer.from('hello');
console.log(buf);        // <Buffer 68 65 6c 6c 6f>
console.log(buf.length); // 5
console.log(buf[0]);     // 104（'h' 的 ASCII 碼）

// Buffer 不能調整大小
buf[0] = 72;  // 'H'
console.log(buf.toString()); // 'Hello'

// 合併 Buffer
const a = Buffer.from('Hello ');
const b = Buffer.from('World');
const c = Buffer.concat([a, b]);
console.log(c.toString()); // 'Hello World'

面試中為什麼 Buffer 重要

  • Streams 預設 emit Buffer — 你必須知道這件事
  • Buffer 在 V8 之外 — 大 Buffer 不會觸發主執行緒的 GC
  • buf.toString('utf8') 轉成字串；Buffer.from(str) 轉回來

6. 練習題

題目 1：用 stream 串流檔案傳給 HTTP response 比用 readFile 好在哪？

答：記憶體用量。readFile 把整個檔案載入 RAM 才送出去。2GB 的檔案就是 2GB RAM。Stream 一邊讀一邊送 — RAM 用量固定 ~64KB，不管檔案多大。而且 response 更快開始（第一個 byte 在檔案還沒讀完前就送出去了）。

題目 2：你想一邊讀檔案一邊加密，要用哪種 stream？

答：Transform stream。讀取（Readable）→ 加密（Transform）→ 寫入（Writable）。

題目 3：Buffer.from('hi').length 是多少？為什麼？

答：2。每個字母在 UTF-8 佔 1 個 byte。Buffer.length 是 byte 數，不是字元數。中文字（如「嗨」）會佔 3 個 bytes。

7. 面試完整回答

"Streams 是 Node 處理大量資料的方式 — 不一次載入全部記憶體，而是資料一到就處理。有四種型別：Readable、Writable、Duplex、Transform。內建的 .pipe() 方法把它們串起來，並自動處理 backpressure — 目的地跟不上時暫停來源，等 drain 事件後恢復。

"我用 streams 處理檔案上傳、日誌處理、串流影音。關鍵優勢是記憶體效率：2GB 的檔案串流用 ~64KB RAM。不用 stream 的話，要嘛整包載入記憶體，要嘛 crash。

"Streams 預設 emit Buffer — V8 heap 之外的原始二進位資料。要文字的話用 .toString() 轉換。二進位資料（圖片、影片）Buffer 就是我們要的。"
