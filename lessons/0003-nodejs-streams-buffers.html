Node.js Interview

Lesson 3: Streams & Buffers

The second-most-asked Node.js deep-dive topic. Streams are how Node handles large data without eating all your RAM.

Prerequisite: Lesson 1 (Event Loop)

Why This Matters

Interviewers ask about streams to test whether you understand how Node handles real-world data at scale. Anyone can read a file with readFileSync — knowing when and why to use streams separates backend engineers from scripters.

1. The Problem Streams Solve

// Bad — loads entire file into memory
const fs = require('fs');
const data = fs.readFileSync('huge-file.log', 'utf8');
// Memory usage: size of the whole file (could be 500MB)

// Good — processes chunk by chunk
const readStream = fs.createReadStream('huge-file.log', 'utf8');
readStream.on('data', (chunk) => {
  console.log(`Received ${chunk.length} bytes`);
});
// Memory usage: only ~64KB at a time (default highWaterMark)

Without streams: you wait for the entire file/response to load into RAM, then process it.
With streams: you process data as it arrives, in small chunks.

Interview script: "Streams let me process data piece-by-piece instead of loading everything into memory. For a 2GB file, streams use ~64KB of RAM. Without streams, the same operation would crash the process."

2. The Four Types

TypeDirectionExample
ReadableSource → youfs.createReadStream, HTTP request body
WritableYou → destinationfs.createWriteStream, HTTP response
DuplexBoth directionsTCP socket, WebSocket
TransformModify data in transitzlib.createGzip, encryption
// Readable: read data
const readable = fs.createReadStream('input.txt');

// Writable: write data
const writable = fs.createWriteStream('output.txt');

// Duplex: read AND write (like a phone call)
// Transform: modify data as it passes through (like a translator)
const { Transform } = require('stream');
const upperCase = new Transform({
  transform(chunk, encoding, callback) {
    callback(null, chunk.toString().toUpperCase());
  }
});

// Pipe them together: read → transform → write
readable.pipe(upperCase).pipe(writable);
// "hello" → "HELLO" → written to output.txt

3. Pipe — The Key Concept

.pipe() is the glue. It connects a Readable stream to a Writable stream and handles backpressure automatically.

// Serve a file via HTTP — the classic interview example
const http = require('http');
const fs = require('fs');

http.createServer((req, res) => {
  // Stream the file directly to the response
  // No buffering, no waiting for the full file
  const stream = fs.createReadStream('big-video.mp4');
  stream.pipe(res);
}).listen(3000);

stream.pipe(res) does three things:

  1. Reads chunks from the file
  2. Writes them to the HTTP response
  3. Pauses the read if the response is slower than the file read (backpressure)

4. Backpressure — The Tricky Part

Backpressure is what happens when the writer is slower than the reader. Without it, data would pile up in memory and crash the process.

// What pipe() does internally:
const readable = fs.createReadStream('source.txt');
const writable = fs.createWriteStream('dest.txt');

readable.on('data', (chunk) => {
  const canWriteMore = writable.write(chunk);
  if (!canWriteMore) {
    // Destination is overwhelmed — pause the source
    readable.pause();
    writable.once('drain', () => {
      // Destination is ready for more — resume
      readable.resume();
    });
  }
});
Interview trap: If you manually listen to 'data' events and .write() without handling backpressure, you'll buffer unlimited data in memory. This is why .pipe() is the safe default — it handles backpressure for you.
Interview script: "Backpressure happens when the writable stream can't keep up with the readable stream. .pipe() handles it automatically — it pauses the source when the internal buffer fills, and resumes on the 'drain' event."

5. Buffers — Raw Binary Data

A Buffer is a fixed-size chunk of raw memory allocated outside the V8 heap. Every stream chunk is a Buffer (unless you specify encoding).

// Create a buffer from a string
const buf = Buffer.from('hello');
console.log(buf);        // <Buffer 68 65 6c 6c 6f>
console.log(buf.length); // 5
console.log(buf[0]);     // 104 (ASCII code for 'h')

// Buffers are NOT resizable
buf[0] = 72;  // 'H' in ASCII
console.log(buf.toString()); // 'Hello'

// Combine buffers
const a = Buffer.from('Hello ');
const b = Buffer.from('World');
const c = Buffer.concat([a, b]);
console.log(c.toString()); // 'Hello World'

Why Buffers matter in interviews

  • Streams emit Buffers by default — you need to know this
  • Buffers live outside V8 — large buffers don't trigger garbage collection on the main thread
  • buf.toString('utf8') converts to string; Buffer.from(str) converts back

6. Puzzles

Puzzle 1: What's the advantage of serving a file via fs.createReadStream().pipe(res) instead of fs.readFile()?

Answer: Memory usage. readFile loads the entire file into RAM before sending it. For a 2GB file, that's 2GB of RAM. The stream sends chunks as they're read — RAM usage stays at ~64KB regardless of file size. Also, the response starts faster (first byte arrives before the file is fully read).

Puzzle 2: What type of stream would you use to encrypt data while reading it from a file?

Answer: A Transform stream. You read from the file (Readable), pass through the encryption Transform, then write to a file or socket (Writable).

readable.pipe(encryptTransform).pipe(writable);

Puzzle 3: What happens if you pipe() without the writable handling backpressure?

Answer: .pipe() handles backpressure automatically — it pauses the readable when writable.write() returns false and resumes on 'drain'. This is built into pipe. The danger is when you manually listen to 'data' and call .write() yourself without checking the return value.

Puzzle 4: If a Buffer has 5 bytes, what is Buffer.from('hi').length?

Answer: 2 — each character is 1 byte in UTF-8. Buffer.length === number of bytes, not characters. For multi-byte characters (like '嗨'), it would be more.

7. Interview Answer Script

When the interviewer says "Tell me about streams in Node.js":

"Streams are how Node handles large data without loading it all into memory. There are four types: Readable, Writable, Duplex, and Transform. The built-in .pipe() method connects them and handles backpressure — when the destination can't keep up, it pauses the source and resumes on the drain event.

"I use streams for file uploads, log processing, and serving media files. The key advantage is memory efficiency: a 2GB file streamed over HTTP uses ~64KB of RAM. Without streams, the same operation would buffer the entire file in memory or crash.

"Streams emit Buffers by default — raw binary data allocated outside the V8 heap. I convert to strings with .toString() when I need text, but for binary data (images, video), Buffers are exactly what I want."
