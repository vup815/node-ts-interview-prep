TypeScript Interview

Lesson 5: Interface vs Type vs Class

三個東西的區別、用途、互相搭配方式。

0. 先記住一件事

編譯後存在？可以 new？可以 merge？可以有實作？
interface❌ 完全消失❌✅❌ 只有簽名
type❌ 完全消失❌❌❌ 只有簽名
class✅ 變成 JS class✅❌✅ 有實作

interface 和 type 在 runtime 不存在。class 是真的存在於 JS 裡的東西。

1. interface — 開放式合約

本質：宣告一個可擴充的插槽。

interface User { name: string }

// 可以再打開加東西（declaration merging）
interface User { age: number }

// User 現在是 { name: string; age: number }

interface 右邊只能放 物件形狀（`{ ... }`）：

interface A { x: number }           // ✅
interface B = { x: number }         // ❌
interface C = string | number        // ❌
interface D = Partial<User>          // ❌
interface E { [K in keyof User]: T } // ❌

interface 可以做的事：

// 函式簽名
interface Greeter { (name: string): string }

// 繼承
interface Admin extends User { role: string }

// class 保證遵守
class MyUser implements User {
  name = 'Ada'; age = 30
}

2. type — 封閉式別名

本質：右邊型別表達式的代號。可以放任何型別。

type A = { x: number }              // ✅ 物件
type B = string | number             // ✅ union
type C = [string, number]            // ✅ tuple
type D = Partial<User>               // ✅ 計算結果
type E = { [K in keyof User]: T }    // ✅ mapped
type F = string                      // ✅ primitive alias

// type 不能 declaration merging
type User = { name: string }
type User = { age: number }          // ❌ Duplicate

type 可以做的事：

// interface 做不到的 4 件事
type Status = 'pending' | 'success' | 'error'
type Pair<T> = [T, T]
type Nullable<T> = { [K in keyof T]: T[K] | null }
type Fn = (x: number) => string

3. class — 型別 + 實作

本質：一次給你型別簽名 + JS 實作。TypeScript 的 class 只是 JS 的 class 加上型別標註。

class User {
  name: string
  age: number

  constructor(name: string, age: number) {
    this.name = name
    this.age = age
  }

  greet(): string {
    return `Hi, I'm ${this.name}`
  }
}

// 用 class
const u = new User('Ada', 30)
u.greet() // "Hi, I'm Ada"

// class 本身也可以當型別
const u2: User = new User('Bob', 25)

編譯後長這樣：

class User {
  constructor(name, age) {
    this.name = name
    this.age = age
  }
  greet() {
    return `Hi, I'm ${this.name}`
  }
}

所有型別標註都消失了。

4. 互相搭配

class implements interface/type

interface Shape { area(): number }

class Circle implements Shape {
  constructor(public radius: number) {}
  area() { return Math.PI * this.radius ** 2 }
}

type 從 class 取型別

class User {
  constructor(
    public id: number,
    public name: string,
    public email: string,
    public password: string,
  ) {}
}

// 直接從 class 型別變形，不需要另外寫 interface
type CreateUserPayload = Omit<User, 'id'>
type UpdatePayload = Partial<CreateUserPayload>
type PublicProfile = Pick<User, 'id' | 'name'>

interface 從 class 繼承（少見但可以）

class User { name = 'Ada' }
interface ExtendedUser extends User { role: string }

const u: ExtendedUser = { name: 'Ada', role: 'admin' }

5. 實際選擇策略

// 1. 只是傳遞資料的形狀 → type（預設）
type User = { id: number; name: string }

// 2. 需要擴充 library 型別 → interface
declare module 'express' {
  interface Request { user?: User }
}

// 3. 需要 new + 行為 → class
class Logger {
  log(msg: string) { console.log(msg) }
}

// 4. union / mapped / 計算型別 → type
type Result<T> =
  | { status: 'success'; data: T }
  | { status: 'error'; message: string }
  | { status: 'loading' }
一句話總結：資料形狀用 type，擴充用 interface，行為用 class。

6. 面試 script

"interface 是開放式宣告 — 它建立一個可 merge 的插槽。我唯一用它是在擴充第三方型別（比如往 Express Request 加 user）。

"type 是封閉式別名 — 它可以表達 interface 做不到的事：unions、tuples、mapped types、utility type 的計算結果。我預設用 type 定義所有資料形狀。

"class 跟上面兩個完全不是同一類東西 — 它編譯後存在於 JS 裡，可以被 new，可以攜帶實作。我只有在需要封裝狀態和行為時才用 class。

"這三個可以互相搭配：class 可以 implements interface/type，type 可以從 class 用 utility types 變形，interface 也可以 extends class。"

8. 練習題

題目 1：你想定義一個 API 回應型別，可能成功（有 data）或失敗（有 error）。用 interface 還是 type？為什麼？

type — 因為這是 union：type ApiResult<T> = { ok: true; data: T } | { ok: false; error: string }。interface 不能表達 union。

題目 2：你要擴充 Express 的 Request，加上 user 屬性。用 interface 還是 type？

interface — 需要 declaration merging：declare module 'express' { interface Request { user?: User } }。type 不能 merge。

題目 3：你需要一個 User 型別，但不想重複定義 id、name、email。你的程式已經有一個 User class。怎麼做？

直接用 class 當型別：class User { constructor(public id:number, public name:string, public email:string){} }。然後用 utility types 變形：type PublicUser = Omit<User, 'email'>。

9. 面試追問題

追問：class 可以 implements type 嗎？

可以，只要 type 是物件形狀：type Shape = { area(): number }; class Circle implements Shape { area() { return Math.PI * 2 } }。

追問：為什麼 utility types（Partial、Pick）可以用在 interface 上？

因為 interface 和 type 對 utility types 來說是同一回事 — 它們看的都是結構（shape），不是定義方式。interface 定義的物件 shape 和 type 定義的一樣都可以被工具型別變換。
