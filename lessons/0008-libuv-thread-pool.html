Lesson 8: libuv Thread Pool & Worker Threads

「Node 是單執行緒」這句話的完整真相。

Prerequisite: Lesson 1 (event loop)

完整真相：Node 不是真的只有一個執行緒

「Node 是單執行緒」指的是 你的 JavaScript 跑在一個執行緒上。但底下 libuv 還有：

  • 一個執行緒跑 event loop（主執行緒）
  • 四個執行緒的 thread pool（預設）
  • 事件迴圈本身也有數個內部執行緒

1. 什麼跑在主執行緒？什麼跑在 thread pool？

主執行緒（JS）libuv thread pool（4 threads 預設）
你的所有程式碼fs 檔案操作
CPU 運算DNS lookup
網路 I/O（HTTP/TCP）crypto（pbkdf2, randomBytes）
zlib 壓縮
重點：網路 I/O（HTTP、socket）不用 thread pool — 它是作業系統層面的非同步。檔案系統和 crypto 才需要 thread pool，因為它們本身是 blocking 的系統呼叫。

怎麼確認？用程式跑一次

const fs = require('fs')

// 同步檔案讀取 — 會 blocking 主執行緒
fs.readFileSync('file.txt')

// 非同步檔案讀取 — 丟給 thread pool，主執行緒繼續跑
fs.readFile('file.txt', () => console.log('done'))
console.log('runs first')  // ✅ 先印這個

2. Thread pool 的大小

// 預設 4 個執行緒
console.log(process.env.UV_THREADPOOL_SIZE)  // undefined → 預設 4

// 可以改（要在程式啟動時、載入模組前設定）
process.env.UV_THREADPOOL_SIZE = 8
require('fs')  // 之後才載入 fs

效能含義：如果你的程式同時做 8 個檔案讀取，但 thread pool 只有 4 個，就有 4 個會排隊等前面的完成。

const crypto = require('crypto')

// 同時啟動 6 個 pbkdf2（很吃 CPU 的 crypto）
const start = Date.now()
for (let i = 0; i < 6; i++) {
  crypto.pbkdf2('password', 'salt', 100000, 64, 'sha512', () => {
    console.log(`#${i} done in ${Date.now() - start}ms`)
  })
}

// 預期輸出：前 4 個差不多同時完成，後 2 個多等一輪
// 因為 thread pool 只有 4 個執行緒可以同時跑

3. CPU 密集任務：為什麼會 block event loop

// ❌ 這會凍結整個 server
function sumTo(n: number) {
  let sum = 0
  for (let i = 0; i < n; i++) sum += i
  return sum
}

app.get('/heavy', (req, res) => {
  const result = sumTo(1_000_000_000)  // 跑在主執行緒 → 所有請求都卡住
  res.json({ result })
})

主執行緒被 CPU 運算佔住，event loop 無法處理任何 I/O — 每個請求都延遲。

解法三選一

// 1. Worker threads — 把工作丟到另一個執行緒
const { Worker } = require('worker_threads')

const worker = new Worker(`
  const { parentPort } = require('worker_threads')
  let sum = 0
  for (let i = 0; i < 1e9; i++) sum += i
  parentPort.postMessage(sum)
`, { eval: true })

worker.on('message', result => res.json({ result }))
worker.on('error', err => res.status(500).json({ error: err.message }))

// 2. Cluster — 多個 process，每個有自己的 event loop
const cluster = require('cluster')
const http = require('http')
const numCPUs = require('os').cpus().length

if (cluster.isPrimary) {
  console.log(`Primary ${process.pid} is running`)
  // 產生跟 CPU 數量一樣多的 worker process
  for (let i = 0; i < numCPUs; i++) {
    cluster.fork()
  }
} else {
  // worker process 各自跑 server
  http.createServer((req, res) => {
    res.writeHead(200)
    res.end('Hello')
  }).listen(8000)
  console.log(`Worker ${process.pid} started`)
}

// 3. 如果是 crypto/compress 這類 — 已經支援 thread pool，直接用就好
crypto.pbkdf2(...)  // ✅ 自動用 thread pool

4. Worker Threads vs Cluster

Worker ThreadsCluster
執行緒 or 程序執行緒（共享記憶體）程序（隔離記憶體）
能共享狀態？✅（SharedArrayBuffer, Atomics）❌ 只能透過 IPC 訊息
記憶體較少每個 process 一份

5. 面試 script

當面試官問「Node 是單執行緒嗎？怎麼處理並行？」：

"不完全對。你的 JavaScript 跑在單一主執行緒上，但底下有 libuv — 它提供 event loop 和一個預設 4 個執行緒的 thread pool。

"I/O 密集的工作（檔案、網路、crypto）交給 thread pool 或作業系統，所以主執行緒不會被卡住 — 這就是為什麼 Node 可以同時處理上千個連線。

"但 CPU 密集的工作（大量計算、壓縮、JSON.stringify 大物件）會佔住主執行緒，block 所有請求。解法有三：worker_threads 做平行運算、cluster 開多個 process、或把 crypto/compress 這類工作用內建的 thread pool 函式。

"worker_threads 共享記憶體適合單一任務的平行化，cluster 適合把流量分散到多個 process。"

6. 練習題

Puzzle 1: 哪個操作會 block event loop？

  • a) fs.readFile('a.txt', cb)
  • b) fs.readFileSync('a.txt')
  • c) fetch('https://api.example.com')
  • d) crypto.pbkdf2(...)

b) 只有 readFileSync 會 block — 它同步跑在主執行緒。fetch 用作業系統層面的非同步網路，pbkdf2 和 readFile（非同步版）都用 thread pool。

Puzzle 2: 你的 server 同時啟動 10 個 pbkdf2 呼叫，thread pool 是 4。會發生什麼？

前 4 個同時在 thread pool 上跑，剩下的 6 個排隊等。當其中一個完成，下一個才會開始。這是 I/O 密集場景的效能瓶頸 — 可以把 UV_THREADPOOL_SIZE 調大（如果機器有更多核心）。

Puzzle 3: 你要平行處理 100 萬筆資料做格式轉換。用 worker_threads 還是 cluster？為什麼？

worker_threads。這是單一任務的平行化 — 所有 worker 處理同一份工作的不同分片。worker_threads 共享記憶體（SharedArrayBuffer）省去序列化成本，比 cluster 的 IPC 傳輸快。cluster 適合「多個獨立請求同時進來的 web server」情境。
