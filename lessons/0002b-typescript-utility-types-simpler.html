TypeScript 面試

Lesson 2b: Utility Types 基礎

只教 3 個最常用的 utility types。簡單、實用、面試必考。

什麼是 Utility Type？

Utility type 是一個內建的型別助手 — 它吃進一個型別，產出一個新型別。你不需要自己寫轉換邏輯，TypeScript 已經準備好了。

// 你有一個型別：
interface User {
  id: number;
  name: string;
  email: string;
}

// Utility types 幫你變形：
type PartialUser = Partial<User>;  // 全部欄位變 optional
type JustName   = Pick<User, 'name'>;  // 只留 name
type NoEmail    = Omit<User, 'email'>;  // 去掉 email

你可以把它想成陣列的 .map() / .filter()，但這是給型別用的。

1. Partial<T> — 「全部欄位可選」

interface User {
  id: number;
  name: string;
  email: string;
}

type PartialUser = Partial<User>;
// 結果：{ id?: number; name?: string; email?: string; }

面試中使用情境

PATCH endpoint — 使用者只傳想更新的欄位：

async function updateUser(
  id: number,
  changes: Partial<User>
): Promise<User> {
  // 只有 changes 裡的欄位會被合併
  return db.users.update(id, changes);
}

// 使用：只傳要改的
updateUser(1, { name: "新名字" });         // ✅
updateUser(1, { id: 2 });                  // ✅ Partial 允許
updateUser(1, { name: "A", email: "b@c.com" }); // ✅
面試腳本：「我用 Partial<T> 處理 PATCH endpoint — 呼叫端只傳想改的欄位。省去另外定義一個 UpdateUserPayload 型別。」

2. Pick<T, Keys> — 「選取子集」

interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  createdAt: Date;
}

// 只選要曝光的欄位
type PublicProfile = Pick<User, 'id' | 'name'>;
// 結果：{ id: number; name: string; }

面試中使用情境

DTO 投影（Projection） — API 不該回傳 password 或內部欄位：

function getProfile(user: User): PublicProfile {
  return {
    id: user.id,
    name: user.name,
  };
  // 如果不小心回傳 password，TypeScript 會報錯
}

3. Omit<T, Keys> — 「排除子集」

interface User {
  id: number;
  name: string;
  email: string;
  password: string;
}

// 移除不想要的欄位
type SafeUser = Omit<User, 'password'>;
// 結果：{ id: number; name: string; email: string; }

Pick vs Omit 怎麼選？

PickOmit
你知道要保留哪些Pick<T, 'id' | 'name'>
你知道要移除哪些Omit<T, 'password'>

原則：5 個欄位要留 2 個 → 用 Pick。5 個欄位要移除 1 個 → 用 Omit。

4. 進階：組合使用

interface User {
  id: number;
  name: string;
  email: string;
  password: string;
}

// 「更新使用者」的 payload：id 不能改，其他可選
type UpdateUserPayload = Partial<Omit<User, 'id'>>;
// 結果：{ name?: string; email?: string; password?: string; }

// 使用
function updateUser(id: number, changes: UpdateUserPayload) { ... }

updateUser(1, { name: "新名字" });  // ✅
updateUser(1, { name: "新", password: "secret" });  // ✅
updateUser(1, { id: 2 });  // ❌ Error: id 不在 UpdateUserPayload 中
面試腳本：「我組合 utility types — Partial<Omit<User, 'id'>> 意思是『id 之外全部可選』。這樣就不用為每個場景定義一個型別。」

5. 練習題

題目 1：Pick<User, 'email'> 的結果是什麼？

interface User { id: number; name: string; email: string; }

答案：{ email: string; }

題目 2：Omit<User, 'id' | 'name'> 的結果是什麼？

interface User { id: number; name: string; email: string; }

答案：{ email: string; }

題目 3：用 Partial<User> 當 PATCH payload 會有什麼問題？

答案：Partial<User> 會讓 id 變成可選（id?: number），代表使用者可能不小心改到自己的 ID。正確做法是 Partial<Omit<User, 'id'>>，把 id 徹底移掉。

6. 面試完整回答

"我常用三個 utility types。Partial<T> 讓全部欄位變可選 — 適合 PATCH endpoint。Pick<T, K> 選取子集 — 用於 API 回應只曝光特定欄位。Omit<T, K> 排除欄位 — 用於移除敏感資料如 password。

"我也會組合它們 — Partial<Omit<User, 'id'>> 的意思是『id 不能改，其他可選』。重點是不需要為每個場景手動定義型別，utility types 會從原始型別推導出來。"

  • Mapped types（[K in keyof T]）— utility type 的內部實作
  • Discriminated unions — 狀態機模式
  • Conditional types — infer、extends ? :
