TypeScript Interview

Lesson 2b: Utility Types (Simpler)

Only 3 utility types. Gentle examples. No mapped types. No conditional types.

Mission: Backend engineer interview prep

What is a Utility Type?

A utility type is a built-in helper that takes an existing type and produces a new type from it. You don't write the transformation yourself — TypeScript gives it to you.

// You have this:
interface User {
  id: number;
  name: string;
  email: string;
}

// Utility types transform it:
type PartialUser = Partial<User>;  // all fields become optional
type JustName   = Pick<User, 'name'>;  // only 'name'
type NoEmail    = Omit<User, 'email'>;  // everything except 'email'

Think of them like array methods (.map(), .filter()) — but for types instead of values.

1. Partial<T> — "all fields optional"

interface User {
  id: number;
  name: string;
  email: string;
}

type PartialUser = Partial<User>;
// Result: { id?: number; name?: string; email?: string; }

When to use it in an interview

PATCH endpoint — the client only sends the fields it wants to update:

async function updateUser(
  id: number,
  changes: Partial<User>
): Promise<User> {
  // Only `changes` fields will be merged
  return db.users.update(id, changes);
}

// Usage: only pass what changed
updateUser(1, { name: "New Name" });         // OK
updateUser(1, { id: 2 });                    // OK (Partial allows this)
updateUser(1, { id: 2, name: "A", email: "b@c.com" }); // OK
Interview script: "I use Partial<T> for PATCH endpoints where the caller only sends the fields they want to change. It saves me from defining a separate 'UpdateUserPayload' type."

2. Pick<T, Keys> — "select a subset"

interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  createdAt: Date;
}

// Pick only the fields you want to expose
type PublicProfile = Pick<User, 'id' | 'name'>;
// Result: { id: number; name: string; }

When to use it in an interview

DTO projection — your API shouldn't return password or internal fields:

function getProfile(user: User): PublicProfile {
  return {
    id: user.id,
    name: user.name,
  };
  // TypeScript error if you try to return password by accident
}

3. Omit<T, Keys> — "exclude a subset"

interface User {
  id: number;
  name: string;
  email: string;
  password: string;
}

// Remove the fields you don't want
type SafeUser = Omit<User, 'password'>;
// Result: { id: number; name: string; email: string; }

Pick vs Omit — which one?

PickOmit
You know which fields to keepPick<T, 'id' | 'name'>
You know which fields to removeOmit<T, 'password'>

Rule of thumb: If you're keeping 2 out of 5 fields, use Pick. If you're removing 1 out of 5, use Omit.

4. Bonus: Combining them

interface User {
  id: number;
  name: string;
  email: string;
  password: string;
}

// "update user" payload: everything except id, everything optional
type UpdateUserPayload = Partial<Omit<User, 'id'>>;
// Result: { name?: string; email?: string; password?: string; }

// Usage
function updateUser(id: number, changes: UpdateUserPayload) { ... }

updateUser(1, { name: "New" });  // OK
updateUser(1, { name: "New", password: "secret" });  // OK
updateUser(1, { id: 2 });  // Error: id is not in UpdateUserPayload
Interview script: "I compose utility types — Partial<Omit<User, 'id'>> is 'everything optional except id'. This avoids defining a dozen one-off types."

5. Puzzles (Easy)

Puzzle 1: What type does Pick<User, 'email'> produce?

interface User { id: number; name: string; email: string; }

Answer: { email: string; }

Puzzle 2: What type does Omit<User, 'id' | 'name'> produce?

interface User { id: number; name: string; email: string; }

Answer: { email: string; }

Puzzle 3: What's wrong with using Partial<User> for UpdateUserPayload instead of Partial<Omit<User, 'id'>>?

Answer: Partial<User> would make id optional (id?: number), which means someone could accidentally change the user's ID in an update. Partial<Omit<User, 'id'>> removes id entirely so it's not even in the type.

Puzzle 4: Your team has this type:

interface BlogPost {
  id: number;
  title: string;
  content: string;
  authorId: number;
  createdAt: Date;
  updatedAt: Date;
}

You need a type for "creating a new post" (no id, no dates, but all other fields required). What utility types do you use?

Answer: Omit<BlogPost, 'id' | 'createdAt' | 'updatedAt'>

6. Interview Answer Script

When the interviewer says "Tell me about some utility types you use":

"I use three utility types regularly. Partial<T> to make all fields optional — great for PATCH endpoints. Pick<T, K> to select a subset of fields — I use it for API responses that only expose certain fields. And Omit<T, K> to exclude fields — useful for removing internal data like password from a user type.

"I also compose them — Partial<Omit<User, 'id'>> gives me 'everything optional except the ID.' The key is that I don't need to manually redefine types for each scenario; the utility types derive the new type from the original."
