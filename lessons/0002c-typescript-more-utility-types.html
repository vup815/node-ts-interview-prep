Lesson 2c: Utility Types 進階

Record、ReturnType、Awaited — 一樣用簡單 pace，跟 Partial/Pick/Omit 組合使用。

先修：Lesson 2b（Partial, Pick, Omit）

1. Record<K, V> — 「有型別的字典」

// 沒用 Record：index signature
type RolePermissionsOld = {
  [role: string]: string[];
};

// 用 Record：key 是明確的 union
type Role = 'admin' | 'user' | 'guest';
type RolePermissions = Record<Role, string[]>;

Record<K, V> 建立一個物件型別，其中K 的每個成員對應到值型別 V。

使用時機

// 各環境的設定
type Env = 'development' | 'staging' | 'production';
type AppConfig = Record<Env, { apiUrl: string; debug: boolean }>;

const config: AppConfig = {
  development: { apiUrl: 'http://localhost:3000', debug: true },
  staging:     { apiUrl: 'https://staging.example.com', debug: true },
  production:  { apiUrl: 'https://example.com', debug: false },
};

// 少寫一個環境？TypeScript 報錯給你：
// Property 'production' is missing in type

2. ReturnType<T> — 「取出函式的回傳型別」

function getUser() {
  return { id: 1, name: 'Ada' };
}

// 不用重複定義：
// interface User { id: number; name: string; }

// 直接從函式推導：
type User = ReturnType<typeof getUser>;
// 結果：{ id: number; name: string; }

使用時機：不要重複定義型別

import { createUser } from './api';

function handleCreateUser(name: string, email: string) {
  // createUser 回傳 Promise<{ id: number; name: string; email: string }>
  // 不用另外寫 interface，直接推導
  type CreateUserResult = ReturnType<typeof createUser>;
  // 結果：Promise<{ id: number; name: string; email: string }>
}

3. Awaited<T> — 「解開 Promise」

async function fetchUser() {
  return { id: 1, name: 'Ada' };
}

// 只用 ReturnType 會拿到 Promise：
type Raw = ReturnType<typeof fetchUser>;
// 結果：Promise<{ id: number; name: string }>

// 加上 Awaited 才拿到真正的型別：
type User = Awaited<ReturnType<typeof fetchUser>>;
// 結果：{ id: number; name: string }

組合使用 — 後端最常見的模式

import { getUser, updateUser } from './api';

// 從 API 函式推導使用者的型別 — 零重複
type User = Awaited<ReturnType<typeof getUser>>;

// 然後就可以用在各種地方：
function displayUser(user: User) {
  console.log(user.name);  // 有型別！
}

// 甚至推導 update 的 payload：
type UpdatePayload = Partial<Omit<User, 'id'>>;

function updateCurrentUser(changes: UpdatePayload) {
  return updateUser(changes);
}

4. 總複習：目前學的 6 個

Utility功能使用時機
Partial<T>全部 optionalPATCH 請求
Pick<T, K>只留這些 keyAPI 回應投影
Omit<T, K>移除這些 key隱藏敏感欄位
Record<K, V>有固定 key 的字典設定、權限、對照表
ReturnType<T>取出函式回傳型別從既有函式推導型別
Awaited<T>解開 Promise配合 ReturnType 處理非同步

5. 練習題

題目 1：Record<'x' | 'y', number> 的結果是什麼？

答案：{ x: number; y: number; }

題目 2：Item 的型別是什麼？

function fetchItem() {
  return Promise.resolve({ id: 1, name: 'Widget', price: 9.99 });
}
type Item = Awaited<ReturnType<typeof fetchItem>>;

答案：{ id: number; name: string; price: number; }

題目 3：你的團隊有函式 getSession()，回傳 Promise<{ userId: number; token: string; expiresAt: number }>。你想定義一個不包含 token 的型別。怎麼寫？

type Session = Awaited<ReturnType<typeof getSession>>;
type SafeSession = Omit<Session, 'token'>;

6. 面試完整回答

"我在後端會組合三種模式。第一，Record<K, V> 處理有固定 key 的字典 — 環境設定、角色權限、HTTP 狀態碼對照表。編譯器會強迫每個 key 都存在。

"第二，ReturnType<typeof fn> 從既有 API 函式推導型別。當我包裝 fetchUser 時，不用手動重定義回傳型別。

"第三，Awaited<ReturnType<typeof fn>> 解開非同步函式。這是我型別策略的核心：一個真實來源（API 函式），零手動重複的型別。"
