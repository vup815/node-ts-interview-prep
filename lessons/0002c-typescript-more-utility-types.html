Lesson 2c: More Utility Types

Record, ReturnType, Awaited — same gentle pace as Lesson 2b.

Prerequisite: Lesson 2b (Partial, Pick, Omit)

1. Record<K, V> — "typed dictionary"

// Without Record: index signature
type RolePermissionsOld = {
  [role: string]: string[];
};

// With Record: keys are explicit
type Role = 'admin' | 'user' | 'guest';
type RolePermissions = Record<Role, string[]>;

Record<K, V> creates an object type where every key in K maps to value type V. The keys come from a union type.

When to use it

Any time you want a lookup table or enum-based dictionary:

// Config per environment
type Env = 'development' | 'staging' | 'production';
type AppConfig = Record<Env, { apiUrl: string; debug: boolean }>;

const config: AppConfig = {
  development: { apiUrl: 'http://localhost:3000', debug: true },
  staging:     { apiUrl: 'https://staging.example.com', debug: true },
  production:  { apiUrl: 'https://example.com', debug: false },
};

// TypeScript error if you miss an environment:
// Property 'production' is missing in type '{ development: ...; staging: ...; }'
Interview script: "I use Record<K, V> when I need a dictionary with known keys — role permissions, environment configs, HTTP header maps. The compiler catches missing keys."

2. ReturnType<T> — "extract a function's return type"

function getUser() {
  return { id: 1, name: 'Ada' };
}

// Instead of duplicating the type:
// interface User { id: number; name: string; }

// Derive it from the function:
type User = ReturnType<typeof getUser>;
// Result: { id: number; name: string; }

When to use it

Don't duplicate types — derive them from the functions that already exist:

import { createUser } from './api';

function handleCreateUser(name: string, email: string) {
  // createUser returns Promise<{ id: number; name: string; email: string }>
  // Without ReturnType, you'd create a separate interface
  type CreateUserResult = ReturnType<typeof createUser>;
  // Result: Promise<{ id: number; name: string; email: string }>
}

// Common pattern: wrap an API function and keep its return type
async function apiCall<T>(fn: () => Promise<T>): Promise<T> {
  try {
    return await fn();
  } catch (e) {
    console.error(e);
    throw e;
  }
}

// ReturnType<typeof fn> is T — the generic handles it automatically
Interview script: "I use ReturnType<typeof fn> to derive types from existing functions instead of duplicating them. If the function changes, the derived type updates automatically."

3. Awaited<T> — "unwrap a Promise"

async function fetchUser() {
  return { id: 1, name: 'Ada' };
}

// ReturnType alone gives you the Promise:
type Raw = ReturnType<typeof fetchUser>;
// Result: Promise<{ id: number; name: string }>

// Awaited unwraps the Promise:
type User = Awaited<ReturnType<typeof fetchUser>>;
// Result: { id: number; name: string }

Combining ReturnType + Awaited — the real pattern

// This is the most common combo in backend code:
import { getUser, updateUser } from './api';

// Derive the user type from the API function — zero duplication
type User = Awaited<ReturnType<typeof getUser>>;

// Now use it anywhere:
function displayUser(user: User) {
  console.log(user.name);  // typed!
}

// Even for update payloads:
type UpdatePayload = Partial<Omit<User, 'id'>>;

function updateCurrentUser(changes: UpdatePayload) {
  return updateUser(changes);
}
Interview script: "I combine Awaited<ReturnType<typeof fn>> to unwrap async function returns. This means I never manually write an interface that matches what the API already returns — it's derived automatically."

5. Puzzles

Puzzle 1: What type does Record<'x' | 'y', number> produce?

Answer: { x: number; y: number; }

Puzzle 2: What's the type of Item?

function fetchItem() {
  return Promise.resolve({ id: 1, name: 'Widget', price: 9.99 });
}

type Item = Awaited<ReturnType<typeof fetchItem>>;

Answer: { id: number; name: string; price: number; }

Puzzle 3: Your team has a function getSession() that returns Promise<{ userId: number; token: string; expiresAt: number }>. You need a type for the session without the token. Write the type using utility types.

Answer:

type Session = Awaited<ReturnType<typeof getSession>>;
type SafeSession = Omit<Session, 'token'>;

Puzzle 4: Why does this fail?

type Status = 'pending' | 'approved' | 'rejected';
const statusMessages: Record<Status, string> = {
  pending:  'Waiting for review',
  approved: 'Changes approved',
  // Error: Property 'rejected' is missing
};

Answer: Record<Status, string> requires every key in the Status union to be present. rejected is missing, so TypeScript errors. This is the feature — not a bug — it prevents incomplete configurations.

6. Interview Answer Script

When the interviewer says "What utility types do you use in a backend context":

"I combine three patterns. First, Record<K, V> for typed dictionaries — environment configs, role permissions, HTTP status code maps. The compiler enforces that every key is present.

"Second, ReturnType<typeof fn> to derive types from existing API functions. When I wrap fetchUser in a middleware, I don't manually redefine the return type — I derive it.

"Third, Awaited<ReturnType<typeof fn>> to unwrap async functions. This is the backbone of my type strategy: one source of truth (the API function), zero manually-duplicated types."
