TypeScript 面試

Lesson 4: Narrowing & Type Guards

如何把模糊的型別變成精確的型別 — TypeScript 面試最實用的技巧之一。

先修：Lesson 2b（utility types）

為什麼重要

真實的程式碼 — 和面試中 — 你不斷收到寬型別的資料，然後需要安全地操作它。Narrowing 就是你精煉寬型別的方法。沒有它，什麼都是 any 或 unknown，失去所有型別安全。

1. 什麼是 Narrowing？

Narrowing 是 TypeScript 把一個 union type 收窄到某個特定成員的過程，依據執行時期的檢查。

// 寬型別
function process(value: string | number) {
  // 這裡 value 是 string | number — 什麼都不能做

  if (typeof value === 'string') {
    // 這個 block 裡，value 被收窄成 string
    console.log(value.toUpperCase());  // ✅ 可以
  } else {
    // 這個 block 裡，value 被收窄成 number
    console.log(value.toFixed(2));     // ✅ 可以
  }
}

typeof 檢查就是一個 type guard — 它告訴 TypeScript 在 if block 裡面可以信任這個型別。

2. typeof — 最常見的 guard

function format(input: string | number | boolean): string {
  if (typeof input === 'string') {
    return input.toUpperCase();
  }
  if (typeof input === 'number') {
    return input.toFixed(2);
  }
  // 到這裡 TypeScript 知道 input 是 boolean
  return input ? 'yes' : 'no';
}

typeof 可以檢查什麼

  • 'string'、'number'、'boolean'、'symbol'、'bigint'、'undefined'、'object'、'function'
  • ⚠️ typeof null === 'object' — 這是 JS 的 bug。需要另外檢查 null。

3. instanceof — 給 class 用的

class ApiError extends Error {
  constructor(public statusCode: number, message: string) {
    super(message);
  }
}

function handleError(err: Error | string) {
  if (err instanceof ApiError) {
    // 收窄成 ApiError — 有 .statusCode
    console.log(`API ${err.statusCode}: ${err.message}`);
  } else if (err instanceof Error) {
    // 收窄成 Error
    console.log(`一般錯誤：${err.message}`);
  } else {
    // 收窄成 string
    console.log(`字串訊息：${err}`);
  }
}

4. 'in' 運算子 — 檢查屬性是否存在

interface Car { wheels: number; drive(): void; }
interface Boat { length: number; sail(): void; }

function operate(vehicle: Car | Boat) {
  if ('drive' in vehicle) {
    // 收窄成 Car
    vehicle.drive();
  } else {
    // 收窄成 Boat
    vehicle.sail();
  }
}

5. Discriminated Unions — 最乾淨的模式

與其檢查哪些屬性存在，不如檢查一個共同的 literal discriminant：

type ApiResult<T> =
  | { status: 'success'; data: T }
  | { status: 'error'; message: string }
  | { status: 'loading' };

function handleResult(result: ApiResult<User>) {
  switch (result.status) {
    case 'success':
      // 收窄：result.data 是 User ✅
      console.log(result.data.name);
      break;
    case 'error':
      // 收窄：result.message 是 string ✅
      console.error(result.message);
      break;
    case 'loading':
      console.log('載入中...');
      break;
  }
}

6. 自訂 Type Guard

當 typeof 或 instanceof 不夠用時，你可以用 value is Type 語法寫自訂 guard：

interface User { name: string; email: string; }
interface Admin extends User { role: 'admin'; }

function isAdmin(user: User): user is Admin {
  return 'role' in user && user.role === 'admin';
}

function processUser(user: User) {
  if (isAdmin(user)) {
    // 收窄成 Admin — 有 .role
    console.log(`Admin: ${user.name}, role: ${user.role}`);
  } else {
    // 收窄成 User（不是 Admin）
    console.log(`User: ${user.name}`);
  }
}

回傳型別 user is Admin 告訴 TypeScript：「如果這個函式回傳 true，把參數當作 Admin 來處理。」

7. Exhaustiveness Check（never）

當你對 union 加入新成員，你希望編譯器提醒你沒處理到的 case：

type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number }

function area(s: Shape): number {
  switch (s.kind) {
    case 'circle':
      return Math.PI * s.radius ** 2;
    case 'square':
      return s.side ** 2;
    default:
      // 如果以後加 triangle，這裡會報錯：
      // Type 'triangle' is not assignable to type 'never'
      const _exhaustive: never = s;
      return _exhaustive;
  }
}
面試陷阱：沒有 never default，加入 triangle 後編譯器不會報錯。函式在執行時期回傳 undefined。never check 在編譯期抓到這個問題。

9. 練習題

題目 1：以下各 branch 的收窄型別是什麼？

function test(x: string | number | null) {
  if (typeof x === 'string') { /* ??? */ }
  else if (typeof x === 'number') { /* ??? */ }
  else { /* ??? */ }
}

string、number、null — else branch 拿到剩下的型別。

題目 2：這段程式碼有什麼問題？

function getLength(x: string | string[]) {
  if (typeof x === 'object') {
    return x.length;
  }
  return x.length;
}

typeof null === 'object' — 如果 x 是 null，第一個 branch 會當掉。應該用 Array.isArray(x) 來檢查陣列。

題目 3：如果 Shape union 加了 { kind: 'triangle'; base: number; height: number }，但 area 函式沒有 never check，會發生什麼事？

編譯器不會報錯，但執行時期 area({ kind: 'triangle', base: 3, height: 4 }) 會回傳 undefined — 沒有任何錯誤或警告。never check 強迫你處理每個 variant。

10. 面試完整回答

"Narrowing 是 TypeScript 根據執行時期檢查收窄 union type 的能力。最常用的 guard 是 typeof（基本型別）、instanceof（class）、'property' in obj（檢查屬性是否存在）。

"對於有多種變體的物件型別，我用 discriminated unions — 每個成員有一個 literal kind 或 status 屬性，用 switch 收窄。我還會加 default: never 做 exhaustiveness check，讓編譯器在漏掉 case 時報錯。

"複雜邏輯的話，我寫自訂 type guard，用 value is Type 回傳型別語法 — 把執行時期檢查封裝起來，下游能拿到收窄後的型別。"

11. 更多 Discriminated Union 範例

Fetch 回應狀態

type FetchState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: Error }

function render(state: FetchState<User>) {
  switch (state.status) {
    case 'idle': return '尚未開始';
    case 'loading': return '載入中…';
    case 'success': return state.data.name;  // ✅ 有 data
    case 'error': return state.error.message; // ✅ 有 error
  }
}

WebSocket 訊息

type ServerMessage =
  | { type: 'chat'; sender: string; text: string }
  | { type: 'join'; username: string }
  | { type: 'leave'; username: string }
  | { type: 'system'; code: number }

function handleMessage(msg: ServerMessage) {
  switch (msg.type) {
    case 'chat': console.log(`${msg.sender}: ${msg.text}`); break;
    case 'join': console.log(`${msg.username} 加入了`); break;
    case 'leave': console.log(`${msg.username} 離開了`); break;
    case 'system': console.log(`系統代碼 ${msg.code}`); break;
    default: const _exhaustive: never = msg;
  }
}

驗證結果（面試常考）

type ValidationResult =
  | { ok: true; value: number }
  | { ok: false; errors: string[] }

function parsePositiveInt(input: string): ValidationResult {
  const n = Number(input);
  if (!Number.isInteger(n) || n <= 0) {
    return { ok: false, errors: ['必須是正整數'] };
  }
  return { ok: true, value: n };
}

const result = parsePositiveInt('abc');
if (result.ok) {
  result.value;  // ✅ number
} else {
  result.errors; // ✅ string[]
}
