Node.js 面試

Lesson 10: CommonJS vs ESM

Node.js 的兩個模組系統 — 面試必考題，考你對 runtime 的理解深度。

為什麼這題重要

面試官很愛問「require 和 import 差在哪？」因為這題能快速判斷你對 Node.js 的理解程度 — 不只是會用哪個語法，而是懂不懂同步 vs 非同步的載入機制、tree-shaking、以及整個生態系的遷移方向。大多數人會用但講不清楚 trade-off。

1. 兩個系統一覽

CommonJS (CJS)ES Modules (ESM)
語法require() / module.exportsimport / export
載入方式同步（會 blocking）非同步（不 blocking）
Node 預設.js（無 "type":"module"）.mjs 或 "type":"module"
Tree-shaking❌ 不可能✅ 打包工具可消除未用到的 export
Top-level await❌ 不支援✅ 支援
條件式載入✅ 可在 if 裡 require⚠️ 只能用 dynamic import()
靜態分析❌ 無法靜態分析依賴✅ import 可靜態分析
執行時期呼叫 require() 當下解析執行前先解析完所有 import

2. 語法比較

// ── CommonJS ──
const fs = require('fs');
const { readFile } = require('fs');
module.exports = { myFunction };
exports.myFunction = () => {};

// ── ES Modules ──
import fs from 'fs';
import { readFile } from 'fs';
export const myFunction = () => {};
export default myFunction;

3. 最關鍵的差異：同步 vs 非同步

這是面試官會深入追問的地方。

// CJS：require() 是同步的 — 下一行程式碼要等模組載入完才執行
const lodash = require('lodash');
console.log('ready');  // 等 lodash 完全載入後才執行

// ESM：import 會被提升（hoisted）— 所有模組在執行程式碼前就解析完
import lodash from 'lodash';
console.log('ready');  // 在所有模組解析完後才執行

條件式載入 — 實際影響

// ✅ CJS — 可以在 if 裡面 require（這是 CJS 的優勢）
let logger;
if (process.env.NODE_ENV === 'production') {
  logger = require('./logger-prod');
} else {
  logger = require('./logger-dev');
}

// ❌ ESM — static import 只能在頂層
// import logger from './logger-dev';  // 錯誤：不能放在 if 裡

// ✅ ESM — 用 dynamic import()，但它是非同步的
if (process.env.NODE_ENV === 'production') {
  const logger = await import('./logger-prod.js');
}

4. CJS 的 module wrapper

CJS 的每個檔案都被包在一個函式裡，這就是為什麼 require、module、exports、__dirname、__filename 看起來是全域變數但其實是區域的：

// Node 實際上把你的程式碼包成這樣：
(function(exports, require, module, __filename, __dirname) {
  // 你的程式碼在這裡
  const fs = require('fs');
  module.exports = { ... };
});

// ESM 沒有這個 wrapper — 沒有 __dirname、__filename
// 需要用 import.meta.url 來替代：
import { fileURLToPath } from 'url';
import { dirname } from 'path';
const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

5. 循環依賴（Circular Dependency）

這是面試的進階題。兩個系統的行為不同：

// a.js (CJS)
const b = require('./b');
console.log('a 載入完成');

// b.js (CJS)
const a = require('./a');  // a 還沒載入完，拿到的是 partial exports
console.log('b 載入完成');

// CJS 的行為：b 拿到的是 a 目前已經 export 的部分（可能是空物件）
// 不會報錯，但可能拿到 undefined

// ESM 的行為：
// import 是 live binding — 如果 a 還沒執行完，b 會拿到 reference
// 但 ESM 不允許循環依賴中有未定義的 binding，會報 ReferenceError
// 所以 ESM 對循環依賴更嚴格

6. Node 怎麼決定用哪個系統

// package.json 是開關
{
  "type": "module"    // ← 這個 package 底下的 .js 都是 ESM
}
{
  "type": "commonjs"  // ← 這個 package 底下的 .js 都是 CJS（預設）
}

// 副檔名可以覆蓋：
//   .mjs → 永遠是 ESM，不管 package.json
//   .cjs → 永遠是 CJS，不管 package.json

7. 面試完整回答

"新專案應該用 ESM — 它是 JavaScript 標準規格，支援 tree-shaking（打包時自動移除沒用到的程式碼）、top-level await，而且是整個生態系的未來方向。但 CommonJS 仍然廣泛存在於既有專案和 npm 套件中，所以我必須熟悉兩種語法。

"兩者最根本的差異是載入行為：require() 是同步的，可以在條件式裡面使用；import 是靜態的、會被提升到頂層。如果要在 ESM 裡面做動態載入，我用 import()，它回傳一個 Promise。

"另外要注意的是，CJS 有 module wrapper function（所以有 __dirname），ESM 沒有，需要用 import.meta.url 來替代。ESM 對循環依賴也比 CJS 嚴格。"

8. 面試追問題

追問 1：你在一個 ESM 專案裡，想用 moment.js（CJS 套件），可以用嗎？

可以，ESM 可以用 import 載入 CJS 套件。Node 會自動處理轉換。但反過來，CJS 不能 require() ESM 套件（除非用 dynamic import）。

追問 2：為什麼 tree-shaking 在 CJS 無法實現？

因為 CJS 的 require() 可以在任何地方執行（if 裡、函式裡），打包工具無法在編譯期靜態分析哪些 export 有被用到。ESM 的 import 只能在頂層，靜態結構固定，所以打包工具可以安全地刪除未使用的 export。

追問 3：import() 和 require() 都是動態載入，差在哪？

require() 是同步的（會 blocking），回傳的是 module.exports 的內容。import() 是非同步的，回傳的是 Promise，resolve 後的物件包含所有 export（包含 default 和 named）。import() 可以用在 CJS 和 ESM 中，但 require() 不能在 ESM 中使用。
