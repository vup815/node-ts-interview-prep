Node.js 面試

Lesson 1: Event Loop

Node.js 面試中最重要的題目。能講清楚 event loop，就能掌握整個面試的節奏。

為什麼這題重要

每場 Node.js 面試至少會有一題 event loop — 可能是輸出順序題，也可能是「解釋非同步怎麼運作」。面試官回報，event loop 是區分表面理解和深層理解的第一道關卡。這堂課給你完整的心理模型和口頭回答腳本。

1. 心理模型

單執行緒 + libuv

JavaScript 跑在一個執行緒上。它無法同時做兩件事。當你呼叫 fs.readFile 或 setTimeout，Node 把工作交給 libuv — 一個 C 語言寫的函式庫，負責管理 I/O、計時器和一個執行緒池。工作完成後，libuv 把 callback 排入佇列，等 JS 呼叫栈空了之後，event loop 再來處理。

關鍵觀念：「單執行緒」指的是你的 JavaScript 程式碼跑在一個執行緒上。libuv 的執行緒池（預設 4 個執行緒）負責處理阻塞操作（檔案讀寫、加密）。Event loop 是連接兩者的橋樑。

六個 Phases

Event loop 循環六個 phase。面試中你會需要講清楚的 phase：

Phase執行的東西相關 API
timers到期的 setTimeout / setInterval callbacksetTimeout(fn, 0)
pending callbacks延遲的系統 callback（如 TCP 錯誤）內部使用
idle / preparelibuv 內部記帳內部使用
pollI/O callback（檔案讀取、網路）fs.readFile、http
checksetImmediate callbacksetImmediate(fn)
close callbacks清理事件（如 socket.on('close')）內部使用

Microtask — 陷阱所在

每個 phase 之間，event loop 會檢查 microtask 佇列。它們的優先級高於任何 macrotask。

佇列優先級API
nextTick 佇列最高process.nextTick(fn)
Promise microtask 佇列第二Promise.resolve().then(fn)、queueMicrotask(fn)、await

完整執行順序

1. 執行當前的同步程式碼（call stack）
2. 清空整個 nextTick 佇列
3. 清空整個 Promise microtask 佇列
4. 執行一個目前 phase 的 macrotask（例如一個 timer callback）
5. 再次清空整個 nextTick 佇列
6. 再次清空整個 Promise microtask 佇列
7. 移到下一個 phase，重複步驟 4
餓死 Event Loop：遞迴呼叫 process.nextTick 會讓 nextTick 佇列永遠清不空，event loop 永遠走不到 poll phase，所有 I/O 都無法處理。這就是為什麼 Node 官方警告不要濫用 nextTick。

3. 輸出順序題

先預測輸出結果，再點開看答案。

題目 1：基本順序

console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve().then(() => console.log('3'));

console.log('4');

輸出：1, 4, 3, 2

為什麼：1 和 4 先同步執行。Promise 的 .then 是 microtask — 在 call stack 清空後、下一個 macrotask 之前執行。setTimeout(0) 是 macrotask — 在下一個 timers phase 執行。

題目 2：nextTick vs Promise

Promise.resolve().then(() => console.log('promise'));
process.nextTick(() => console.log('nextTick'));
console.log('sync');

輸出：sync, nextTick, promise

為什麼：sync 先跑。nextTick 佇列在 Promise 佇列之前清空 — nextTick 在 microtask 中有最高優先級。

題目 3：在 I/O callback 裡 — setImmediate vs setTimeout

const fs = require('fs');
fs.readFile(__filename, () => {
  setTimeout(() => console.log('timeout'), 0);
  setImmediate(() => console.log('immediate'));
});

輸出：immediate, timeout

為什麼：在 I/O callback 裡面時，event loop 正在 poll phase。poll 之後會到 check（setImmediate），然後 close callbacks，最後才回到 timers（setTimeout）。所以在 I/O 內部，setImmediate 永遠比 setTimeout 先跑。

在 I/O 外部，setTimeout 和 setImmediate 的順序是不確定的 — 取決於計時器何時到期。

題目 4：巢狀 Microtask

process.nextTick(() => {
  console.log('nextTick 1');
  process.nextTick(() => console.log('nextTick 2'));
});

Promise.resolve().then(() => {
  console.log('promise 1');
  process.nextTick(() => console.log('nextTick 3'));
});

console.log('sync');

輸出：sync, nextTick 1, nextTick 2, promise 1, nextTick 3

為什麼：整個 nextTick 佇列在 Promise 佇列之前清空。即使 nextTick 2 是在 nextTick callback 裡面被加入的，它仍然在同一次清空中執行。nextTick 佇列清空後，Promise 佇列才開始。但 nextTick 3 是在 Promise callback 裡被加入的 — 它會在下一次 microtask 清空時執行（Promise 佇列清完後、下一個 phase 之前）。

題目 5：Async/await — 經典陷阱

async function foo() {
  console.log('a');
  await bar();
  console.log('c');
}

async function bar() {
  console.log('b');
}

foo();
console.log('d');

輸出：a, b, d, c

為什麼：foo() 同步執行到 await。console.log('a') 先跑，然後 bar() 被呼叫。bar() 同步執行（印 b），回傳一個 resolved promise。await 暫停 foo，把控制權交還給呼叫者（全域範圍）。console.log('d') 執行。foo 的續段（await 之後的部分）被排成 microtask，在 call stack 清空後執行。

面試陷阱：很多人以為 c 在 d 之前。他們忽略了 await 會把控制權交還給呼叫者。

4. 面試完整回答

當面試官問「解釋 event loop」，用這份腳本：

"Event loop 讓 Node.js 可以在一個執行緒上處理數千個並行連線。底層的 C 函式庫 libuv 負責執行這個循環，它依序經過六個 phase：timers、pending callbacks、poll、check、close callbacks。每個 phase 有自己的 FIFO 佇列。

"每個 phase 之間，Node 會清空兩個 microtask 佇列：首先是 process.nextTick，然後是 Promise microtask。這就是為什麼 nextTick 比 .then callback 先執行，也為什麼深度遞迴的 nextTick 可能會餓死 I/O。

"關鍵的心理模型：同步加入的 microtask 在任何 macrotask 之前執行。所以 Promise.resolve().then(...) 比 setTimeout(...) 先跑，即使 delay 是 0。而在 I/O callback 裡面，setImmediate 比下一個 setTimeout 先觸發，因為 check phase 在 timers phase 之前。"

為什麼這段話有效：提到 libuv（展現深度）、說出 phase 名稱（展現結構）、解釋 microtask vs macrotask（展現精確度）、舉例說明（展現實戰理解）。

5. 常見追問題

追問：「什麼東西跑在 libuv 的執行緒池上？」

答：檔案系統操作（fs）、DNS（dns.lookup）、部分加密操作（crypto.pbkdf2、crypto.randomBytes）。網路 I/O（HTTP、TCP）使用作業系統核心 — 不經過執行緒池。

追問：「poll phase 如果沒有 timer 也沒有 I/O 會發生什麼事？」

答：Poll phase 會檢查是否有 setImmediate callback。如果有，立刻移到 check phase。如果沒有，它會 blocking 等待 I/O 事件。如果有一個 timer 即將到期，它會跳過等待直接移到 timers phase。

追問：「Event loop 會永遠跑下去嗎？」

答：不會。當沒有 handle（timer、I/O socket）或 request 需要處理時，event loop 就會停止。Loop 在 libuv 裡是透過 uv_run 執行的 — 當 libuv 回傳時，Node 就結束了。
