TypeScript Interview

Lesson 11: satisfies & as const

Modern TS features appearing in 2026 interviews — type-checking without widening.

Why This Matters

Interviewers ask about satisfies (TS 4.9+) because it reveals whether you understand the tension between type-checking and type-widening. as const tests literal types.

1. The Problem: Type Assertion Widens

const config = { port: 3000, debug: true } as Record<string, unknown>;
config.port; // type: unknown ❌ — lost the number type

as tells TypeScript "trust me" — but it widens the type and discards literal values.

2. satisfies: Check Without Widen

const config = { port: 3000, debug: true } satisfies Record<string, unknown>;
config.port; // type: number ✅ — preserved!

satisfies checks conformity without changing the inferred type.

3. Key Difference

  • as Type = "make this Type" (widens, discards detail)
  • satisfies Type = "check this matches, keep narrowest type"

4. as const — Literal Types

// Without as const — widened
const roles = ['admin', 'user', 'guest'];  // type: string[]

// With as const — literal
const roles = ['admin', 'user', 'guest'] as const;
// type: readonly ['admin', 'user', 'guest']

// Extract union from array
type Role = typeof roles[number]; // 'admin' | 'user' | 'guest'

5. Combining Both

const config = {
  apiUrl: 'https://api.example.com',
  port: 3000,
  roles: ['admin', 'user'] as const,
} satisfies Record<string, unknown>;

// config.port: number (not unknown)
// config.roles: readonly ['admin', 'user']

6. Interview Script

"satisfies (TS 4.9+) checks that a value matches a type without widening it. I use it for config objects and event maps — anywhere I want type safety but need to preserve narrow types. "as const gives me literal types for arrays and objects. Combined with satisfies, I can validate against a constraint while keeping the most specific types for autocomplete and exhaustive checking."

7. Puzzles

Puzzle 1: What's the type difference?

const a = { x: 1 } as Record<string, number>;
const b = { x: 1 } satisfies Record<string, number>;
a.x is number (widened). b.x is 1 (literal). Both pass the type check, but satisfies preserves the original type.

Puzzle 2: What type is Fruit?

const fruits = ['apple', 'banana'] as const;
type Fruit = typeof fruits[number];
'apple' | 'banana' — without as const it would be string.
